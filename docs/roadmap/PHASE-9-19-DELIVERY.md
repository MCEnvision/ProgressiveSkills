# Phase 9 through Phase 19 delivery

This delivery train is cumulative. Each phase checkpoint contains every earlier beta phase, its exact verified JAR, a checksum, an automated evidence record, and a focused fallback checklist.

`main` remains the latest user approved and tested build. Phase branches remain beta builds until the final mass check is approved. Each new phase branch is created from the approved `main` commit and then fast forwarded to the preceding cumulative beta checkpoint before new work begins. Phase tags are created only after approval.

## Added feature set

The following twenty features extend the planned phases. They are part of the delivery train and not replacements for the original phase scope.

### General features

1. Compatibility profiles let a pack choose strict, preferred, or fallback capability bundles and preview what will be disabled.
2. Adapter self tests run bounded nonmutating provider health probes and expose capability and circuit state.
3. Live performance guards identify expensive routes, projections, publishes, and tick work without silently changing gameplay.
4. Deterministic reproduction bundles capture a redacted state snapshot, definition digest, seed, and bounded event sequence for replay.
5. Persistent milestone choices let players select one pack defined reward bundle with stable receipts and an explicit respec policy.
6. Personal training contracts create deterministic bounded goals from eligible skills and resist reroll and clock abuse.
7. Cross skill combo mastery builds configurable tracks from ordered awards with cooldown, cap, and anti farm controls.
8. Party readiness checks let members opt in to share role, selected build, resources, and cooldown readiness.
9. Contribution receipts explain shared XP and challenge credit with privacy safe calculations.
10. The Studio gameplay recorder converts bounded operator actions into redacted declarative test fixtures and never publishes them directly.

### UI features

11. Test Center presents the mass checklist in game, records local progress, shows checkpoint identity, and exports results.
12. Sync Doctor shows connection phase, definition generation, state revision, short digests, resync reason, and a safe resync action.
13. Safe Retry Tray retains rejected intents and can rebuild only safe retryable actions after synchronization.
14. Command Palette provides keyboard first navigation, inspection, ability shortcuts, and safe command discovery.
15. Dual Build Compare compares the current build with two hypothetical plans before server validation.

### Command and accessibility features

16. `/ps doctor` provides pack, compatibility, network, and data checks in readable and JSON forms.
17. `/ps check` provides a resumable mass test runner with start, next, pass, fail, status, finish, and export operations.
18. `/ps why` explains the latest XP, lock, stat, or ability decision in short and verbose narrator friendly forms.
19. Chat only social commands cover party invitations, readiness, consent transfers, and privacy without requiring a mouse.
20. Text Studio commands cover draft status, lint, diff, history, validation, publish confirmation, command palette access, and text graph export.

## Compatibility evidence boundary

External adapters require exact pinned artifacts and successful present mod tests. Until those inputs exist, Phase 15 will deliver the provider contracts, capability negotiation, absent mod safety, vanilla bridges, fallbacks, and circuit breakers. It will report external capabilities as unavailable rather than claiming untested compatibility.

## Manual acceptance boundary

Automated checks can establish deterministic compilation, transactions, persistence, networking guards, GameTests, dedicated server startup, client startup, schema freshness, and release JAR integrity. The final checklist must still cover rendering, narration, real input, two client multiplayer behavior, and a practical play session. `main` moves only after that mass check is approved.
